Move vários cards de uma vez para a mesma etapa de destino e informa quais foram movidos, ignorados ou falharam.

Para o equivalente a selecionar uma coluna inteira, busque os IDs com [IDs dos cards da etapa](/api/crm/movimentacao/listar-ids-da-etapa) e mande o resultado direto em `cardIds`.

## Corpo da requisição

<Params>
<Param name="cardIds" type="int[]" required>
De 1 a 2000 IDs. Duplicados são ignorados.
</Param>
<Param name="targetStageId" type="int" required>
Etapa de destino.
</Param>
<Param name="force" type="bool" required={false}>
`true` confirma mesmo com pendências obrigatórias. Padrão `false`.
</Param>
</Params>

## Resposta

<Response status="200 OK">

```json
{
  "movedCards": [
    {
      "id": 8821,
      "title": "Proposta ACME",
      "stageId": 102
    }
  ],
  "skippedCardIds": [
    8822
  ],
  "failedCardIds": [],
  "stages": [
    {
      "id": 101,
      "totalItems": 9,
      "totalCardValue": 21000
    },
    {
      "id": 102,
      "totalItems": 10,
      "totalCardValue": 46500
    }
  ]
}
```

</Response>

<Callout type="info" title="Skipped não é o mesmo que failed">
`skippedCardIds` é decisão de negócio, `failedCardIds` é falha técnica e admite retry.
</Callout>

<Response status="409 Conflict">

```json
{
  "blockedCards": [
    {
      "cardId": 8821,
      "title": "Proposta ACME",
      "missingFields": [
        {
          "key": "email",
          "label": "E-mail"
        }
      ],
      "pendingTasks": [
        {
          "id": 55,
          "title": "Ligar para o cliente"
        }
      ]
    }
  ],
  "validCardIds": [
    8822,
    8823
  ]
}
```

</Response>

Pendências obrigatórias: com `force: false` e ao menos um card com pendências, **nada é movido**. Dois caminhos a partir daqui:

1. Repetir com `"force": true`, que move todos, inclusive os pendentes.
2. Repetir enviando apenas os `validCardIds`, que move só os completos.

## Campos relevantes

<Fields>
<Field name="movedCards">
Cards efetivamente movidos, já atualizados.
</Field>
<Field name="skippedCardIds">
**Ignorados de propósito**: card fechado, já no destino, de outro funil, ou fora da sua empresa. Não vale repetir.
</Field>
<Field name="failedCardIds">
**Falharam na gravação**: vale repetir a chamada apenas com estes IDs.
</Field>
<Field name="stages">
Totais atualizados de cada etapa de origem envolvida, mais a de destino.
</Field>
</Fields>

## Regras

- Cards que estejam em um funil diferente do da etapa de destino saem como `skipped`. Para mudar de funil, use [Trocar de funil](/api/crm/movimentacao/trocar-de-funil), um card por vez.
- Para volumes grandes, prefira blocos de algumas centenas de IDs em vez de usar o limite máximo de uma só vez.

## Erros

| HTTP | `error` | Quando |
|---|---|---|
| 400 | - | `cardIds` vazio ou acima de 2000 itens; `targetStageId` ausente ou menor/igual a zero |
| 401 | - | Token ausente, inválido ou expirado |
| 403 | - | Permissão apenas de visualização no funil de destino |
| 409 | - | Pendências obrigatórias com `force: false` (corpo com `blockedCards`) |
| 409 | `stage_inactive` | Etapa de destino excluída, bloqueia o lote inteiro |
