Cria uma nova regra com gatilho, condições e ações. Ações de movimento para outra etapa exigem um ID de etapa de destino válido.

## Corpo da requisição

<Params>
<Param name="title" type="string" required>
Título da regra, até 100 caracteres
</Param>
<Param name="trigger" type="int" required>
Tipo de gatilho: `1` atendimento novo, `2` transferido, `3` encerrado, `4` mudou de departamento, `5` mudou de etapa
</Param>
<Param name="funnelId" type="int" required>
ID do funil. Inexistente responde `400`
</Param>
<Param name="conditions" type="array" required>
Ao menos uma condição. Cada item: `{ "field": int, "operator": int, "value": string | array }`. Basta uma ser verdadeira (OU)
</Param>
<Param name="actions" type="array" required>
Pode ser vazio. Cada item: `{ "type": int, "targetStageId": int, "cardStatus": int }`
</Param>
<Param name="isActive" type="bool" required={false}>
Ignorado na criação (toda regra nasce ativa)
</Param>
</Params>

**Ações com `targetStageId`:** Criar card (se vazio, usa a primeira etapa ativa) e mover card (obrigatório, precisa ser do mesmo funil, senão `400`).

**Ações com `cardStatus`:** Valores `1` a `5` como em [Cards](/api/crm/status-e-fechamento/alterar-status-do-card).

## Regras

<Callout type="warn" title="O que as regras executam hoje">
Disparam apenas os gatilhos `1`, `2` e `3`. As condições avaliadas são `field` `1` (usuário), `2` (departamento) e `5` (canal). As ações executadas são `1` (criar card) e `9` (mudar status do card). O restante é aceito no cadastro, mas não tem efeito.
</Callout>

## Erros

| HTTP | `error` | Quando |
|---|---|---|
| 400 | - | Funil não encontrado, etapa de destino inválida ou não pertence ao funil |
